# Уровень размышлений агента: где стоит, как менять, где грабли

Коротко: уровень задаётся один раз в настройках пользователя и действует на ВСЕХ агентов этого
пользователя, во всех очередях. Менять на лету можно, но у переключателя два неочевидных побочных
эффекта — оба описаны ниже, оба проверены на живой очереди 22.08.2026.

## 1. Где он стоит

`~/.claude/settings.json`, ключ `effortLevel`:

```json
{
  "effortLevel": "high"
}
```

Это настройка ПОЛЬЗОВАТЕЛЯ операционной системы, а не проекта. Все агенты, запущенные от этого
пользователя, наследуют её при старте сессии — включая соседние очереди других проектов. Проектной
настройки уровня у нас нет; если она понадобится, заводить её надо осознанно, потому что
пользовательская перестанет быть единственным местом правды.

Уровни, снизу вверх: `low`, `medium`, `high`, `xhigh`, `max`.

## 2. Как поменять умолчание

Правкой того же файла. Действует на НОВЫЕ сессии; уже работающие агенты продолжают со своим.

```bash
cp -p ~/.claude/settings.json ~/.claude/settings.json.bak-$(date +%Y%m%d)
python3 - <<'PY'
import io, json
p = "/home/<пользователь>/.claude/settings.json"
d = json.load(io.open(p, encoding="utf-8"))
d["effortLevel"] = "high"
io.open(p, "w", encoding="utf-8").write(json.dumps(d, ensure_ascii=False, indent=2) + "\n")
PY
```

## 3. Как поменять уровень УЖЕ РАБОТАЮЩЕМУ агенту

Через его REPL-сессию, тем же способом, каким мы вообще пишем работающему агенту:

```bash
tmux send-keys -t claude_<ТАСК>_repl '/effort low' Enter
sleep 3
tmux send-keys -t claude_<ТАСК>_repl '1' Enter     # подтверждение
```

Важно про имя цели: точная форма `-t '=имя'` в этом случае не срабатывает, брать имя сессии без
знака равенства. Проверять результат снимком экрана: `tmux capture-pane -p -t claude_<ТАСК>_repl`.

## 4. Грабли первые: `/effort` переписывает УМОЛЧАНИЕ

После подтверждения интерфейс пишет прямым текстом: «saved as your default for new sessions». То
есть, снизив уровень одному агенту, вы снизили его и всем будущим — включая те задачи, где think
нужен полный. Случай 22.08.2026: уровень опустили одной механической задаче переноса файлов, а
следом в очереди стояли правка боевого сервера и сквозная приёмка, которые молча получили бы тот
же низкий уровень.

**Правило: после каждого `/effort` в живой сессии сразу проверить и вернуть умолчание** в
`~/.claude/settings.json`. Работающая сессия сохранит свой уровень, новые получат нужный.

## 5. Грабли вторые: переключение сбрасывает кеш беседы

Интерфейс предупреждает: «This conversation is cached for the current effort level. Switching means
the full history gets re-read on your next message». На длинной сессии это заметная плата временем
и токенами. Вывод: уровень выбирают на старте задачи, а не крутят по ходу. Менять на лету стоит
тогда, когда до конца работы далеко и выигрыш перекроет перечитывание.

## 6. Что каким уровнем гонять

| работа | уровень | почему |
|---|---|---|
| перенос файлов, зеркала репозиториев, переименования, обновление документации | `low` | решений нет, есть последовательность действий |
| дежурные проверки, снятие замеров, диагностика по готовому списку | `medium` | надо читать вывод, но не изобретать |
| правка боевого сервера, приёмка, миграции, всё, где неверное утверждение стоит живой системы | `high` | цена ошибки выше цены времени |
| действительно трудный разбор: незнакомый протокол, противоречивые данные, поиск причины без гипотезы | `xhigh` / `max` | редко, осознанно, по одной задаче |

## 6а. Заголовки в таск-файле: `Effort:` и `Model:`

Разделы выше — про УМОЛЧАНИЕ пользователя. Оно одно на всех агентов, и крутить его ради одной
задачи неудобно: соседняя очередь получит чужой уровень (§4). Поэтому у очереди есть свой,
пофайловый способ: заголовок в самом таск-файле.

```
Resource-Lock: prod
Effort: high            # low | medium | high | xhigh | max
Model: sonnet           # opus | sonnet | haiku | claude-*
Stall-Limit: 1800
```

Оркестратор читает обе строки при запуске задачи и передаёт агенту ключами `--effort` и
`--model` (`claude_orchestrator.template.sh`, функции `task_effort` и `task_model`). В журнале
очереди это видно строкой запуска:

```
starting T337_… lock=prod max_respawn=0 stall_limit=1800 effort=medium model=sonnet
```

**Обе строки необязательные и обе безопасные.** Нет заголовка — ничего не передаём, агент идёт
на умолчании пользователя, поведение ровно прежнее. Мусор в значении игнорируется по тому же
правилу: лучше запустить задачу на умолчании, чем не запустить вовсе.

**Чем это лучше правки `~/.claude/settings.json`:** уровень и модель выбираются на старте
конкретной задачи и не протекают в соседние. Грабли §4 (`/effort` переписывает умолчание) сюда
не относятся вовсе — настройка пользователя не трогается.

### Какой задаче какая модель

Тот же принцип, что и с уровнем: платить старшей моделью стоит там, где ошибка дороже времени.

| работа | модель | почему |
|---|---|---|
| механическая правка по уже принятому решению, перенос настройки, повтор известного прогона, уборка | `sonnet` | решение принято, нужна аккуратность исполнения, а не поиск |
| правка боевого сервера, миграции, деньги, приёмка, разбор причины | `opus` (умолчание) | цена неверного вывода — живая система или счёт |
| просмотр снимков экрана и прочая работа «посмотреть и описать» | `haiku` | текст наверх идёт короткий, картинку в дорогой контекст тянуть незачем |

🔴 Модель и уровень — РАЗНЫЕ рычаги, и подменять один другим не надо. `Model: sonnet` с
`Effort: high` — нормальное сочетание: младшая модель, думающая столько, сколько нужно. Обратное
(`opus` + `low`) обычно означает, что задачу не разложили как следует.

## 7. Чего снижение уровня НЕ чинит

Отдельные виды отказов от глубины не зависят вовсе, и лечатся они другими механизмами:

* **отчёт без последней строки `STATUS`** — задача уходит в AMBIGUOUS-карантин; лечится правилом в
  таск-файле, а не уровнем;
* **работа осталась незакоммиченной при `SUCCESS`** — лечится гейтом грязного дерева
  (`HOW_TO_RUN.md` §10.0c);
* **отчёт описывает намерение как факт** («правка применена», а в боевом файле её нет) — лечится
  гейтами приёмки, требующими числа и проверку с боевой машины;
* **ожидание внешней системы** — если работа упирается в чужой темп (пауза между запросами к
  площадке, длинная выкатка), уровень не ускорит ничего: время тратится не на размышления;
* **память** — уровень на потребление RAM агентом не влияет. Если очередь стоит на RAM-гейте,
  снижать надо параллельность, а не глубину.
